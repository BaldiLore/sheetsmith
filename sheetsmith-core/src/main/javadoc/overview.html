sheetsmith generates Excel files ({@code .xlsx}) from lists of annotated Java objects, using Apache POI. This module is the core of the library: you describe a table once, with annotations on a class, and pass the data at runtime; sheetsmith writes the title, the header, the rows and the styles, and returns the file as a {@code byte[]}. It has no dependency on Spring and works in any Java 17 or later application; Spring Boot applications use the sheetsmith starter, which adds the auto-configuration.

Example

@ExcelSheet(title = "Customers")
public record CustomerRow(
        @ExcelColumn(header = "Name", order = 10) String name,
        @ExcelColumn(header = "Customer since", order = 20) LocalDate since,
        @ExcelColumn(header = "Revenue", order = 30, format = "#,##0.00") BigDecimal revenue) {
}

Sheetsmith sheetsmith = Sheetsmith.builder().build();   // create once and share

byte[] file = sheetsmith.generate(List.of(SheetData.of("Customers", CustomerRow.class, customers)));

Packages

  • {@link cloud.baldilorenzo.sheetsmith}: the generator, the sheet data, the application defaults and the exceptions.
  • {@link cloud.baldilorenzo.sheetsmith.annotation}: the annotations that describe a sheet class, and the reference of the style cascade.
  • {@link cloud.baldilorenzo.sheetsmith.style}: the enums used as style attribute values, and the presets.
  • {@link cloud.baldilorenzo.sheetsmith.convert}: converters, which turn field values into cell values.

Maven coordinates

<dependency>
    <groupId>cloud.baldilorenzo</groupId>
    <artifactId>sheetsmith-core</artifactId>
    <version>${sheetsmith.version}</version>
</dependency>

Replace {@code ${sheetsmith.version}} with the version of this documentation. In Spring Boot applications, depend on {@code cloud.baldilorenzo:sheetsmith-spring-boot-starter} instead: it brings this module and the auto-configuration.
